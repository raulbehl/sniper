# sniper

Dumps a SystemVerilog testbench's verification constructs to JSON with
[pyslang](https://pypi.org/project/pyslang/) (slang's Python bindings). The output is meant as the
input to turning a constrained-random TB into a formal environment: constraints → assumptions,
drivers → RTL-style logic, coverage → cover properties.

Nothing is tied to a particular testbench. UVM base classes are recognised only to label each
class's role (`uvm_driver`, `uvm_sequence_item`, ...).

```sh
pip install pyslang            # tested with 12.1.0
python sniper.py --own <tb dir> [--own ...] [-o out.json] -- <slang args>
```

`<slang args>` are what you would give the `slang` binary: files, `-f` filelists, `+incdir+`,
`+define+`, `--top`, ... `--own` marks the testbench's own sources; only those are reported in
detail. Packages imported by own code are reported for their types (minus `--skip-pkg`, default
`uvm_pkg`/`ovm_pkg`); add others with `--pkg`.

Example: the AXI UVM TB in `qs-ques-master/tutorials/sv_testbench/axi_slave_testbench/uvm_tb`.
`examples/axi_uvm_tb/sniper.f` holds its slang arguments (paths are relative to that TB directory),
so copy it there and run from the TB directory:

```sh
~/work/myenv/bin/python ~/work/sniper/sniper.py --own . -o axi_uvm_tb_constructs.json -- \
    +incdir+$UVM/src $UVM/src/uvm_pkg.sv -f sniper.f        # UVM: a UVM library checkout
```

## The whole flow: `flow.py`

One project file per testbench runs sniper, then fvgen (smoke runs, witness replay, the RTL run),
and prints each command before it runs it, so any step can be rerun by hand:

```sh
export IBEX=~/work/sniper_corpus/ibex UVM=~/work/sniper_corpus/uvm-core
python flow.py examples/ibex_icache/flow.toml -o icache_out        # --steps fvgen: reuse tb.json
open icache_out/fv/report.md
```

```toml
[testbench]                     # sniper: what the simulator compiles
own  = ["${IBEX}/dv/uvm/icache/dv"]
args = ["--single-unit", "+define+UVM", "-f", "uvm.f", "-f", "tb.f", "--top", "tb"]

[fvgen]                         # any fvgen option by name
run     = true
witness = true

[rtl]                           # optional: the keys of an --rtl-config file, or config = "x.toml"
top       = "ibex_icache"
filelists = ["rtl.f"]
clock     = "clk_i"
reset     = "rst_ni"
reset_active_low = true
depth     = 30
```

Paths are relative to the project file and `${VAR}` comes from the environment, also inside the `.f`
files, so a project can sit next to (or away from) the sources it reads. Outputs: `OUT/tb.json`,
`OUT/fv/` (`report.md`, `fv_*.sv`, `fv_replay.sv`, ...). `--dry-run` prints the commands only.

## Tests

```sh
python tests/test_probe.py          # or: pytest tests/
```

Runs sniper on `tests/probe_tb.sv` and checks the extracted classes, constraints, covergroup
bins/crosses, assertions, randomization sites, stimulus map, config overrides and hierarchy;
`probe_corpus.sv` holds constructs that broke on real testbenches, `probe_fv.sv` what fvgen reads
(widths/signedness, struct offsets, `type_info`, transition steps, option values, functions called
from constraints, `constraint_mode`/`rand_mode` calls), `probe_invalid.sv` code slang cannot bind.
Every extraction bug found on the corpus gets an assertion there.

## Output

| key | content |
|---|---|
| `meta` | pyslang version, command, parse/elaborate/extract time, diagnostics (all errors; everything in own files) |
| `types` | parameters, typedefs, enums with values |
| `classes` | lineage, UVM role, macro-generated flag, properties (type, width, `rand`/`randc`, initializer, enum values, vif/handle/assoc/queue), constraint blocks (`static`, `pure`, `extern` with the out-of-class `body` span) with a typed AST per item (`Expression`, `Implication`, `Conditional`, `Foreach`, `dist` with `:=`/`:/` weights, `soft`, ...), methods, covergroups. A parameterized class nothing specializes is reported through its default specialization (`default_specialization: true`) |
| `subroutines` | every task/function in own files: args, start/end lines, `macro` when generated by a macro, full body AST, and `facts` |
| `procedures` | `initial`/`always`/`final` blocks in own files, same shape |
| `randomization` | every source of randomness: rand members + constraint blocks per class, `obj.randomize() with {...}` (inline constraints in the AST), `std::randomize`, `$urandom*`/`$random`/`$dist_*`, `randcase`, `randsequence` |
| `stimulus` | per class/procedure: interface signals it drives (with blocking/non-blocking) and samples |
| `config` | property defaults, and constant writes made through handles (`c.axi_cfg.ooo_pct = 80`): per-test knob overrides |
| `coverage` | `covergroups` (coverpoints with expr/iff/width, bins with kind and value ranges, transition bins, crosses with their bins, options); `assertions` (`cover`/`assume`/`assert property`, immediate assertions); `counter_coverage_heuristic` (hand-rolled coverage in associative-array counters: sampled key derivations, bins enumerated by executing the report loops, printed totals) |
| `hierarchy` | top instances: parameters, ports, port connections, interface signals and modports; children to `--hier-depth` |

`facts` per routine: `calls`, `timing` (`@`, `#`, `wait`), `loops`, `forks`, `rand_sites`,
`vif_writes`/`vif_reads` (signal accessed through a virtual interface, including `cfg.vif.sig`),
`signal_writes`/`signal_reads`, `field_writes`/`field_reads` (`via_handle` only when the object is
a class handle, not a struct), and `invalid`: code slang could not bind (an error in
`meta.error_list`). Nothing inside an invalid subtree is analysed; `meta.counts.invalid_code` totals
them. Procedures, subroutines and covergroups in generate branches that are not elaborated carry
`uninstantiated: true` and have no body or facts.

AST nodes are `{"k": <slang kind>, "line", "src", "ty" (type), "const" (folded value), ...fields}`;
fields come from reflection over pyslang's classes, so node kinds not seen in testing still serialize.

## Running on real testbenches

Give sniper what the simulator gets. Lessons from running it on ibex, OpenTitan, core-v-verif,
CVA6, Caliptra and riscv-dv:

- `--single-unit`: most flows (VCS/Xcelium) let `` `define``s leak from one file to the next;
  slang does not unless told.
- `--timescale 1ns/1ps` when some files have a `` `timescale`` and others do not (slang errors).
- `--top` every module the simulator elaborates as a top, especially bind-only modules
  (OpenTitan `sim_tops`, `core_ibex_fcov_bind`); otherwise coverage interfaces bound into the DUT
  are not elaborated.
- Use the UVM version the testbench targets (OpenTitan/core-v-verif: UVM 1.2; some newer TBs:
  IEEE 1800.2).
- Code commercial simulators accept but slang rejects ends up in `facts.invalid`: string paths in
  `$assertoff`, a modport taken from a virtual interface handle, virtual interfaces with interface
  ports (UVMF BFMs), class handles in `&&`.

## fvgen: constraints → assumes, coverage → covers

`fvgen.py` turns a sniper extraction into formal collateral for Yosys (`read_verilog -sv -formal`)
and SymbiYosys, the flow of the `qs-ques` formal examples. It reads only sniper's JSON.

```sh
python fvgen.py axi_uvm_tb_constructs.json -o fv/ --run      # --run: smoke-check every module
python fvgen.py tb.json -o fv/ --witness                     # + replay classes: hit a bin in simulation
```

| file | content |
|---|---|
| `fv_constraints.sv` | `fv_c_<class>`: constraint checker. Rand fields and the state the constraints read are inputs; each constraint item is a wire plus an `ASSUME(.., IMPLIES(en, ..))`. Parameters `CM_<block>` (constraint_mode), `SOFT_EN`, `INLINE_EN`. `fv_r_<class>`: `randomize()` model, anyseq values latched when `randomize` is high and constrained in that cycle; outputs hold between calls. One `fv_c_/fv_r_<class>__<site>` per `randomize()` call with inline constraints or an argument list, and per `std::randomize` |
| `fv_covers.sv` | `fv_cg_<owner>__<cg>`: one `cover` per bin (label = bin name) under `sample && iff`; illegal bins are `ASSERT`s (``ifndef FV_NO_ILLEGAL_BINS``); transition bins are monitors over the sampled values |
| `fv_bind.sv` | instantiation templates for covergroups declared in modules/interfaces |
| `fv_replay.sv`, `replay.json` | `--witness`: see below |
| `smoke/` | one top + `.sby` per module, all inputs free: constraints satisfiable (an unsatisfiable set is reported with a minimal conflicting core: file:line and source of each item), every implication/if guard reachable (dead constraint code otherwise), every bin reachable. `--run` runs them (what the `.sby` does: yosys, then `yosys-smtbmc`, without the per-cover trace files sby always writes, which dominated the run time); covergroups with more than `--cover-chunk` bins are split into parallel jobs, each with only its own cover statements; job directories are removed unless `--keep`; a job over `--timeout` is killed with its solver processes and reported as a timeout |
| `report.md/.json` | every constraint item and bin: what it became, **exact / approx / unsupported**, why, and the direction of any approximation |

Constraint semantics (IEEE 1800-2017 clause 18): inheritance with same-name block override; rand
nested objects flattened; `->` and `if/else` as guards; `foreach` unrolled (fixed arrays; dynamic
arrays/queues up to a maximum inferred from `size()` constraints, else `--max-array`, with
`i < size` guards); `inside` with ranges, `$` and array operands; `dist` as membership in the
non-zero-weight items; `unique`; `sum/product/and/or/xor() with`; single-return user functions
(including methods of other objects and functions outside `--own`) inlined; rand enums limited to
their named values; `solve before` ignored (ordering only); `randomize(a, b)` frees only `a`, `b`.
`soft` follows LRM 18.5.13: in priority order (inline over class, derived over base, later over
earlier) a soft constraint is kept only if it is satisfiable with the hard constraints and the
softs already kept. When the constraints involved read only rand variables this is decided at
generation time with yosys `sat` (exact; `--sat-timeout`); when they read testbench state it
depends on the state, and the soft constraint is kept as hard (approx) unless no state allows it
or the call site's inline constraints constrain the same field. Kept softs are under `SOFT_EN`.
A dynamic array whose `size()` can exceed `--max-array` is modelled up to that many elements:
`size()` itself is not capped, later elements are free, and constraints that read the whole array
(reductions, `inside` the array, `unique`, variable indices) hold only while `size()` is within the
model (approx: over, never a false unsat). `constraint_mode(v)` / `rand_mode(v)` calls on the
object before a `randomize()` in the same routine, and on `this` in the class's `new()` /
`pre_randomize()`, set the site's `CM_<block>` defaults / turn the field into state (source order
is assumed to be execution order). Classes are resolved by package when names repeat; module names
are made unique. Expressions keep SV widths: every slang `Conversion` becomes a size cast plus
`$signed/$unsigned`; `**` is lowered (the SMT backends have no `$pow`).

### Hitting a bin in simulation: `--witness`

"Formal reached this bin, no regression seed hits it: how do I hit it?" A simulator seed cannot be
derived from a formal trace (seed -> RNG -> solver is simulator-specific and not invertible), but
the trace's field values can be forced. For every covergroup whose sampled values are fields of a
randomized class (its own fields, a `sample(obj)` argument, or a handle field), `--witness`:

1. drives the covergroup from that class's `randomize()` model, sampled the cycle after a call, and
   only under the `if`/`case` conditions that lead to the testbench's `cg.sample(...)` calls
   (e.g. `case (instr.instr_name) ADD: add_cg.sample(instr)`);
2. reaches every bin and reads, from each trace, the field values of every sampled `randomize()`;
3. writes `fv_replay.sv`: per class `<class>__fv_replay extends <class>` (factory-registered for UVM).
   With `+FV_HIT=<covergroup module>.<cover>` its first calls pin the fields the bin depends on
   (plus the rand fields of the sampling condition) to the witness values; everything else stays
   random under the class's own constraints, so it works with any seed. When the sampling
   condition reads the object's non-rand state (riscv-dv's `instr_name`, set by the generator), each
   step waits for a call made in the witness state.

Run any existing test with the override (`+uvm_set_type_override=<class>,<class>__fv_replay` or
`set_type_override` by type for parameterized classes) and `+FV_HIT=<key>`. `replay.json` and
`report.md` list every bin: **replay** (depends only on pinned fields), **partial** (also on values
the class cannot set: monitor data, testbench state; listed with the witness values),
**unreached** (no sequence of `randomize()` calls within the bound reaches it under the
constraints: no seed will hit it). Assumptions are listed per bin (sampling conditions on other
objects are taken as true). `--covergroups REGEX` limits the run.

### Covergroups on the RTL: `--rtl`

```sh
python fvgen.py tb.json -o fv/ --rtl-config rtl_config.toml
```

The RTL setup comes from the user, in a TOML file (template: `examples/rtl_config.toml`; paths relative
to it; `--rtl-*` options override its entries): `top` (the DUT module), `filelists` (slang `-f` files
of the RTL, read with yosys-slang), `clock`, `reset`, `reset_active_low`, and optionally `binds` /
`bind_tops` (the testbench's bind modules and checkers), `defines`, `depth`. fvgen builds a formal top
with the DUT (inputs free, the reset held for three cycles) and runs each covergroup whose
inputs it can trace into the design, sampled every cycle, so a bin is reached when the design ever
holds that value. Inputs are traced from the extraction alone:

- `sample()` arguments that read a virtual interface signal: through the interface instance in the
  testbench top to the DUT port it is connected to (directly or via a net), or to the DUT-internal
  signal a continuous assign taps (`assign nf_if.rx_sync = dut.uart_core.rx_sync`);
- register-model reads (`ral.reg.field.get_mirrored_value()`): the field's bits in the register's
  backdoor HDL path (`add_hdl_path_slice`, relative to `set_hdl_path_root`);
- fields of a monitored object that a monitor copies from an interface signal.

DUT-internal signals are probed after flattening. The report lists, per covergroup input, the RTL
signal it maps to and why; per bin **reached** (with the cycle), **unreached** (not within
`--rtl-depth`: no proof), or **unmapped** (an input with no RTL counterpart: testbench state).

The **assumptions** in the RTL and in the testbench's bind files (`--rtl-bind`: bind modules and the
checkers they bind, e.g. OpenTitan's `tlul_assert`, whose device side assumes legal bus traffic) are
lowered by `svalower.py` (below) and constrain the runs: they describe the interface. Assertions and
covers of the design and the checkers are left out (the runs are about reaching bins), and so is the
logic only they used. A design that still uses both clock edges runs in multiclock mode (inputs change
at the rising edge, as a clocked driver drives them). Not yet: the testbench drivers' behaviour as
input constraints.

### `svalower.py`: concurrent SVA for yosys-slang

```sh
python svalower.py -o out/ -f rtl.f -f bind.f [--kinds assume]   # out/lowered.f + copies + sva_report.json
```

yosys-slang reads immediate assertions only. Every `assert/assume/cover property` (written directly or
produced by a macro: the macro call is replaced) becomes, in a copy of its file, an immediate assertion
on the property's clock plus flops: `|->` / `|=>` between fixed-delay sequences (`a ##1 b |=> ##2 c`),
`$past(e, n)`, `$rose`, `$fell`, `$stable`, `$changed`, `$isunknown` (0 in two-valued formal),
`disable iff` (an attempt spanning a disabled cycle is cancelled), named sequences and properties
without arguments, `default clocking` / `default disable iff`, `and`/`or` of single-cycle sequences.
A failing attempt is reported at its first unmatched step, as SVA reports it. Not lowered, and listed
with the reason: liveness (`s_eventually`), ranged or unbounded delays, repetition, multi-cycle
`and`/`or`, `throughout`/`until`, local variables, arguments. **T6** checks the lowering against
Verilator's native SVA: on random traces with resets, every lowered property fails at exactly the
cycles the original does.

Coverage semantics (clause 19): value bins, `[]` (one per value) and `[N]` (values split in order,
remainder in the last), wildcard, `with` filters, `iff`, ignore/illegal values removed from every
other bin (fully excluded bins dropped), `default`, automatic bins (enum values, or 2^w values over
`auto_bin_max`), `at_least`, transitions with `[*m:n]`, `[->m:n]`, `[=m:n]` and array transition
bins, crosses with automatic product bins and `binsof/intersect` (`&&`, `||`, `!`) user, ignore
and illegal bins.

`tests/test_fvgen.py`: **T1** proves 66 constraint expressions (mixed signedness, wrap-around,
shifts, `**`, ascending ranges, packed structs, enums, casts, `inside`) equal to yosys-slang's
elaboration of the same SV; **T2** checks whole constraint sets against Verilator's solver in both
directions (its solutions satisfy the assumes; tuples the assumes accept, including boundary
mutations of solutions, are accepted by `randomize() with` pins); **T3** compares every bin and
transition monitor with an LRM reference model on random sample traces; **R** runs
`tests/fv_regress_*.sv` (constructs that broke on the corpus: name collisions across packages and
files, empty inline blocks, truncated arrays, soft priority, mode calls, `this.randomize()`, unsat
cores, ...) through sniper, fvgen and the smoke runs, and checks a hung solver is killed on timeout;
**T4** runs `--witness` on `tests/fv_witness.sv` (class covergroup with transitions/at_least/crosses,
a collector sampled under a `case` on a rand field and an `if` on testbench state) and replays every
reached bin in Verilator with its real constraint solver under three seeds: each must be hit, and a
bin formal found unreachable is never hit in 2000 plain calls; **T5** runs `--rtl` on `tests/rtl_dut.sv` /
`rtl_tb.sv` (a DUT port, an internal net, a register field) and checks the cycle each bin is first reached.

## Notes

- Line numbers are those of the file the construct is written in (include files keep their own
  numbering). Macro-expanded code is placed at the macro's use site with `"macro": <name>`.
- pyslang does not expose slang's `--ast-json` writer; this walks the elaborated AST itself.
- `counter_coverage_heuristic` only enumerates bins whose loops have constant bounds and whose
  keys are built from constants, loop variables and `$sformatf`.
- `tests/probe_tb.sv` exercises constructs: covergroups/bins/crosses, `cover`/`assume property`,
  `dist`, `soft`, `foreach`/`if` constraints, `randomize() with`, `std::randomize`, `randcase`,
  a parameterized class.
